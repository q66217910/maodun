# 矛盾分析

把一个纠缠着多个因素的现实问题，拆成结构清晰、能下手、可检验的判断。

它不是"给建议"的工具，是"看清结构"的工具。结论必须能落到动作上，动作必须能被验证。

## 何时使用

- 用户提出一个多因素纠缠的现实问题：去留、取舍、人际僵局、项目受阻、方向选择、长期困局。
- 用户说"帮我想清楚""我卡住了""不知道该怎么办""这事到底问题在哪"。
- 用户的叙述情绪很重、事实很轻，需要先把事实和判断分开。

不适用：纯事实查询、技术排障、需要专业资质的医疗/法律/心理危机处置。遇到后者，明确建议找专业机构，不要代替专业意见。

## 方法底座

这八条要真正用上，不是拿来当小标题。**具体问题具体分析**贯穿全部：不套模板，不给放之四海而皆准的正确废话。

| 原则 | 出处 | 在分析里做什么 |
| --- | --- | --- |
| 没有调查就没有发言权 | 《反对本本主义》 | 事实与推断严格分开；缺口写成"去问谁、查什么、两种结果各指向哪边" |
| 抓主要矛盾 | 《矛盾论》 | 找出规定或影响其余矛盾的那一个，其余降为次要 |
| 看矛盾的主要方面 | 《矛盾论》 | 哪一方占支配地位、在增强还是在削弱，由此定走向 |
| **矛盾的同一性** | 《矛盾论》 | 对立面**互为存在前提**。找出双方被哪根绳子绑在一起——这决定"能不能切割"，以及为什么很多"走"走不掉 |
| **对抗性与非对抗性** | 《矛盾论》 | 决定"能不能谈"。对抗性只能靠力量对比解决，非对抗性靠调整关系解决；非对抗的处理不当会转成对抗 |
| **发展阶段** | 《论持久战》《矛盾论》 | 量变积累期该守、该攒条件；临近转折该动，拖着就是净损失。不分阶段开药方等于不问病程就下药 |
| 内因是根据，外因是条件 | 《矛盾论》 | 只在外部找原因等于宣布无解；外因通过内因起作用 |
| 认识回到实践检验 | 《实践论》 | 每条结论配检验标准；先小范围试，再从结果校准判断 |

两处容易被忽略的补充：

- **弹钢琴**（《党委会的工作方法》）：抓中心工作，不等于掐掉其他工作。十个指头都要动，只是有节奏、有重点。分析必须回答"哪些事维持最低限度运转"。
- **抓典型**（《关于领导方法的若干问题》）：突破一点、取得经验、再推广。第一步行动应当是小范围试，不是全面铺开。
- **从最坏处准备**（七大口头报告：要在最坏的可能性上建立我们的政策）：方案必须回答最坏会坏到什么程度、损失能不能承受。这不是悲观，是让方案不至于一败涂地。

## 输出结构

固定十段，顺序不可调换。顺序本身是推理链条：看事实 → 看结构 → 定主次 → 定性质 → 定阶段 → 谈条件 → 落到动作。

1. **判断** —— 最多三句，直接说真正的卡点。用户以为的问题不是真问题时，在这里点破。
2. **事实清点** —— 分「已知」与「待核实」。待核实必须写成：查什么 / 问谁 / 两种结果分别把结论推向哪边。不写"需要更多信息"这种空话。
3. **矛盾清单** —— 表格五列：矛盾 / 对立的两方 / 性质 / 当前态势 / 主次。性质填「对抗性」「非对抗性」或「待判」。3-5 条，挖到结构层。
4. **主要矛盾** —— 是哪一条、为什么、判断依据。证据不足就写"暂定"，并说明确认它需要什么。
5. **主要方面** —— 哪一方占主导、在增强还是削弱；**并说明这两方为什么离不开彼此**（依存点具体是什么），由此判断能否切割、切割的代价在谁身上。
6. **阶段** —— 处在量变积累、临近转折，还是已进入新阶段。给依据，并说明不同阶段的策略差在哪。
7. **内因与外因** —— 内因是能改变的（具体行为），外因是只能应对的（不给虚假掌控感）。
8. **转化条件** —— 主次在什么条件下易位；哪些现在就能推动，哪些只能等。只能等的不写进行动。
9. **行动** —— 三步，每步含"做什么 + 检验标准 + 若结果相反说明什么"。第一步 48 小时内可完成、不依赖别人配合，且是**小范围试**；末尾补"哪些事维持最低限度运转"与"最坏情况能不能承受"（从最坏处准备，向最好处努力）。
10. **可能的误判** —— 2-3 条，指出用户最容易骗自己的地方。直白但不刻薄。

第 9 段多出来的「若结果相反，说明」，不是修辞。它是给下一步的**回填接口**：用户做完之后要能把"实际结果"填回来，系统据此判断哪条判断被推翻。没有这一句，行动就只能勾选完成，无法修正认识。

## 边界（重要）

**矛盾不等于敌人。** 矛盾论讲的是普遍存在的对立统一，不是教人去找敌人。日常处境里绝大多数是**非对抗性矛盾**——同事、家人、合作方，矛盾真实存在，但双方还得在同一个统一体里待下去。

分析时的红线：

- 不要使用敌我、斗争、打倒一类语汇描述用户身边的人。
- 不要建议"彻底切割"作为首选，除非同一性已经实际破裂（对方已无法提供你依存的东西，或你已不需要它）。
- 不要把所有冲突都上升为对抗性。凡是可以靠调整规则、边界、分配方式解决的，都是非对抗性的。
- 涉及医疗、法律、严重心理危机的具体处置，交给专业机构，不代替专业意见。

## 语言

- 中文，白话，短句。不堆术语，不引用革命话语做装饰。
- 不评判用户的道德与人格，只分析结构。
- 不用"要努力""要多沟通""要调整心态"这类没有对象的动词——每个动作都要有明确的执行者和完成标志。
- 不用"既要……又要……"来和稀泥，那是没做判断的伪装。
- 不用"本质上""归根结底"开头造句，伪深刻比肤浅更有害。
- 全文 1100-1600 字。宁可少写一条矛盾，不要凑字数。

## 常见失败模式

| 症状 | 本质 | 修法 |
| --- | --- | --- |
| 直接答"走还是留""拆还是不拆" | 没看同一性，把结构问题当成选择题 | 先找依存点，再谈切割 |
| 建议"多沟通" | 没判定矛盾性质 | 先判对抗性，再定方式 |
| 第一段就给三步行动 | 没判阶段 | 先定积累/转折，再定攻守 |
| 把用户说的第一条困扰当主要矛盾 | 没做结构分析 | 先列清单，再比较"牵动几条" |
| 每条矛盾都写"重要" | 不敢做判断 | 强制选一个，其余标次要 |
| 抓了主要矛盾就把别的全丢 | 不会弹钢琴 | 补一句最低限度运转 |
| 转化条件写成心灵鸡汤 | 回避具体条件 | 条件必须能被第三方观察到 |
| 行动写成"制定计划、加强沟通" | 没有执行主体 | 改成"谁、在几天内、做完什么算完" |
| 只写检验标准，不写结果相反说明什么 | 只能勾完成，不能修正判断 | 每步补一句"若结果相反，说明哪条判断错了" |
| 全是同理心，没有判断 | 把分析做成了安慰 | 安慰不解决问题，先给结构 |

## 提示词文件

两份可直接注入的 system prompt。本文件是方法说明，那两份是执行版本：

- `references/analysis-prompt.md` —— 首轮分析（十段完整结构）
- `references/followup-prompt.md` —— 用户补充新事实后的更新（只说"哪里变了"，不重写全文）

两份都带 frontmatter（`role` / `version`），注入前剥掉即可；正文即 system message 全文，放在 `messages[0]`。

## 在本工程里怎么用

网站（`E:\5.git-workspace\maodun`）不内嵌任何提示词文本，运行时由 `server.js` 从本目录读取：

- 目录解析顺序：环境变量 `MAODUN_SKILL_DIR` → `<工程根>/skills/contradiction-analysis`
- 前端请求 `GET /api/prompts` 拿到两份提示词，再拼进 `messages[0]`

所以**改提示词只改这里，不碰代码**，刷新页面即生效，不必重启服务。

## 实践回路（1.2.0）

认识回到实践，不只是"给检验标准"就完事。产品侧现在有三处回填口，缺了它们，方法只走了半程：

| 回填口 | 存哪 | 回流到哪 |
| --- | --- | --- |
| 每步行动的「实际结果 + 符合/部分/相反」 | `case.tasks[k].result` / `.gap` | 「再拆一次」时自动拼进 baseline.practice |
| 「待核实」每条变成可勾工单 + 一句核实到的答案 | `case.checks[k].answer` | 同上，并入新事实 |
| 上次的「可能的误判」 | `baseline.misread` | 重拆时要求逐条对照"这次真的犯了吗" |

改提示词结构时不必动这三处；但只要「行动」或「事实清点」的写法变了，回填口的解析就可能失效——前端的 `syncChecks` 依赖「待核实」这个词和它下面的嵌套列表，改措辞要同步改。
